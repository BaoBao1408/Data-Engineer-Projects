- Evaluate the impact of monthly partitioning on seller-based, time-filtered queries

- Aggregation        : Parallel HashAggregate followed by Finalize GroupAggregate

- Sort Method        : In-memory quicksort
- Memory Usage       : ~30–48 KB per worker
- Planning Time      : 0.294 ms
- Execution Time     : 226.395 ms
Analysis:
- Monthly partitioning enables effective partition pruning, limiting scans to a single partition
- Parallel sequential scan efficiently processes the October data subset
- Aggregation at the seller level is performed in parallel with minimal memory usage
- Sorting operations remain fully in memory without any disk spill
- Execution time is significantly reduced compared to scanning multiple partitions or the full table
- This plan clearly demonstrates the benefit of partitioning for highly selective time-based queries
